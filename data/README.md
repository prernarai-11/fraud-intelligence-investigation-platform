# Data

## Dataset: PaySim

This project uses the **PaySim** synthetic financial dataset — a simulated mobile money transaction log designed to mimic real-world fraud patterns.

**Not included in this repository** due to file size (~470MB, exceeding GitHub's file size limits).

### How to get the dataset

1. Go to the dataset page on Kaggle: [PaySim1 by Edgar Lopez-Rojas](https://www.kaggle.com/datasets/ealaxi/paysim1)
2. Download the dataset (requires a free Kaggle account)
3. Extract the ZIP file — you'll get a CSV, typically named `PS_20174392719_1491204439457_log.csv`
4. Place it in this `data/` folder (or update the file path in the notebook to point to wherever you saved it)

### Dataset summary

| Property | Value |
|---|---|
| Total transactions | 6,362,620 |
| Transaction types | CASH_IN, CASH_OUT, DEBIT, PAYMENT, TRANSFER |
| Fraud cases | 8,213 (~0.13%) |
| Fraud occurs only in | CASH_OUT, TRANSFER |

### Files generated by the notebook (also not included, regenerate by running the notebook)

- `account_risk_data.csv` — full account-level graph features and risk scores (~3.27M rows)
- `transaction_summary.csv` — aggregated transaction stats by type/fraud label (used for Power BI)
- `suspicious_accounts.csv` — flagged accounts with risk scores and reasons (used for Power BI)

### Note on synthetic fraud rings (Phase 2)

Phase 2 of this project injects **synthetic fraud ring scenarios** on top of the real PaySim data (10 circular rings, 14 mule networks, 16 layering chains — 227 additional transactions total). This is because no public dataset labels fraud at the *ring* level, only individual transactions. This injection logic is fully contained in the notebook and regenerates automatically when the notebook is run — no separate file is needed for this.
